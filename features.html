Feature overview

Author packs once, then run every instance as persisted state.

CoreStructuresX separates pack definitions from live instance data and treats every connector, trigger, command, placement job, and failure as explicit state.

Feature overview

Structure generation capabilities

Marked schematics

[CSX] signs define an optional origin, one-shot connectors, and post-paste command points. Marker blocks are replaced during paste.

Weighted groups

groups.yml maps connector ids to weighted schematic candidates, optional per-entry offsets, replacement overrides, fallback groups, and closing groups.

Two expansion modes

AUTOMATIC expands after stability and delay checks. PLAYER_PROXIMITY activates only the connector or command whose saved trigger a player approaches.

Command markers

Weighted console command groups run after paste. Placeholders include transformed coordinates, instance, module, schematic, group, source group, UUID, and structure origin.

Placement safety

Rotation-aware bounds, overlap checks, optional real-block double pass, replaceable-block whitelists, radius and module limits, and lookahead reject unsafe candidates.

Recovery and diagnostics

Pause, resume, stop, inspect, validate, and list instances. Debug and actionbar output can report TPS, MSPT, progress, queues, jobs, and blocked reasons.

Scope

Operational boundaries

Explicit limits

CoreStructuresX is not a world-generation plugin.

No biome or chunk hooks

It does not randomly distribute structures during terrain generation and does not use the world seed.

No Folia support in v1

The current runtime targets Paper and depends on WorldEdit or FastAsyncWorldEdit.

No automatic JSON deletion

Corrupt instance data must be backed up and repaired or moved aside by an administrator.
