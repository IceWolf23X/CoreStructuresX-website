Configuration reference

Configure global safety once, then define each structure as a pack.

The current runtime reads config.yml plus pack-owned pack.yml, structure.yml, groups.yml, optional commands.yml, and schematic files.

Global runtime

Current bundled config.yml

Keep storage type JSON, connector and trigger saving enabled, and paste mode CHUNKED. Test any block budget or stability change on the target server.

config-version: 1

settings:
  debug: false

packs:
  folder: packs

markers:
  header: "[CSX]"
  case-insensitive-header: true
  replacements:
    ORIGIN: AIR
    CONNECTOR: AIR
    COMMAND: AIR

storage:
  type: JSON
  folder: data/instances
  save-connectors: true
  save-triggers: true

validation:
  strict: true
  require-origin: false
  require-all-connectors-resolvable: true

performance:
  paste:
    mode: CHUNKED
    max-blocks-per-tick: 1500
    max-milliseconds-per-tick: 5
    per-job-slice: 256
    max-active-jobs: 16
    max-chunk-loads-per-tick: 2
  schematics:
    max-axis: 512
    max-volume: 1000000
    max-chunks: 1024
  lookahead:
    max-simulation-nodes: 10000
    max-milliseconds: 5
  stability:
    pause-when-tps-below: 18.5
    resume-when-tps-above: 19.5
    pause-when-mspt-above: 45
    resume-when-mspt-below: 35
    stable-samples-required: 5
    sample-interval-ticks: 20

Schematic authoring

Marker sign contract

ORIGIN

Line 1 [CSX], line 2 ORIGIN. Zero markers uses the schematic clipboard origin fallback; more than one is invalid.

CONNECTOR

Line 2 CONNECTOR, line 3 a valid group id, and optional line 4 positive proximity radius. A nonblank zero, negative, or malformed radius is invalid; in proximity mode, every connector needs an explicit or default positive radius.

COMMAND

Line 2 COMMAND, line 3 a valid command-group id, and optional line 4 positive proximity radius. Commands use a persisted at-most-once reservation before console dispatch, preventing deliberate replay after restart.

Signs do not contain directions or dimensions. Rotation and transformed bounds come from the schematic and placement context.

Pack definitions

Required files and responsibilities

FileResponsibility
pack.ymlPack version, id, display metadata, referenced YAML names, and schematics folder.
structure.ymlStart group, generation mode, automatic/proximity settings, lookahead, limits, closing, space checks, paste performance, native facing, and placement offset.
groups.ymlWeighted schematic entries, per-entry offsets and marker replacements, fallback groups, and closing groups.
commands.ymlWeighted console-command entries used by COMMAND markers. Required only when a schematic references a command group.
pack-version: 1
id: abandoned_mine
name: "Abandoned Mine"
version: "1.0.0"
author: "IceWolf23X"
structure: structure.yml
groups: groups.yml
commands: commands.yml
schematics-folder: schematics

All ids must be filesystem-safe; weights must be positive; referenced groups and schematic files must exist. Completion requires no open connectors and no active jobs, so packs that can leave connectors open need closing groups with endpoint schematics. Follow the complete pack authoring guide for a working folder, schematic workflow, marker layouts, full YAML examples, and validation sequence.

Administration

Commands

/csx reload
/csx validate
/csx validate pack <pack-id>
/csx packs list
/csx start <pack-id> [group-id] [world x y z facing] [automatic|proximity <default-radius>] [debug] [actionbar]
/csx instances list
/csx instance info <instance-id>
/csx instance pause <instance-id>
/csx instance resume <instance-id>
/csx instance stop <instance-id>

Console starts require world, coordinates, and a cardinal facing. A player start without coordinates uses the player's block position and snaps yaw to a cardinal direction.

/csx instance info <instance-id> reports state, progress, jobs, connectors, and a per-schematic module usage list with the generated quantity of each module.

Permissions

All permissions default to operators. Keep start permission limited because starting an instance pastes world content.

Persistence and reloads

Protect active instance data.

/csx reload is rejected while any paste job is queued, running, paused, or finalizing. Pausing preserves its exact cursor but does not make reload safe; wait for every paste job to finish. Replacing jars, WorldEdit/FAWE, or the Paper version requires a restart.

Instance JSON under data/instances/ uses data version 4, monotonic revisions, fsynced temporary writes, atomic replacement where supported, and a rolling .json.bak. A corrupt primary is quarantined as .json.corrupt and restored automatically when its backup is valid.

generation.recovery.backtrack-on-blocked must remain false. Destructive module deletion is rejected because prior terrain, NBT, entities, commands, and later external changes cannot be restored losslessly.
