Pack definitions

Files under packs/ describe choices available to future generation. Keep every referenced YAML and schematic path inside its pack directory. Do not point a pack at external files through traversal, symbolic links, junctions or reparse points.

Live instance state

Files under data/instances/ are authoritative runtime state. They contain generated module records, connectors, triggers, command reservations, job phases, checksums and cursors. Never store instance JSON inside a pack folder.

Bundled test pack

The JAR contains bundled-packs/csx_test_pack/ and an explicit file manifest. First start installs it atomically only when the administrator copy does not exist; later starts never overwrite that directory.

Editing rules

Do not replace schematics or pack definitions while an instance using them is actively pasting. Stop the server for manual JSON repair. Use reload only within the boundaries in the next article.
