Before manual repair

  1. Stop Paper.
  2. Back up the affected worlds.
  3. Back up the complete plugins/CoreStructuresX/data/instances/ directory.
  4. Preserve the primary, rolling backup and every migration/invalid/corrupt evidence file.

Atomic saves and rolling backup

A save writes and fsyncs <instance>.json.tmp, retains the previous valid primary as <instance>.json.bak, and atomically replaces the canonical file when supported. Filesystems without atomic move support use a same-directory replacement fallback.

Corrupt primary

If the primary cannot be parsed, the loader tries the rolling backup. A valid backup is accepted only when its instance id matches. The bad primary is preserved as .json.corrupt with a numeric suffix when needed, then the backup is restored through a flushed temporary file.

Version migration

Unversioned data is treated as v1. Versions 1 through 4 are copied to .json.vN.bak before migration to v5. V1/v2 active jobs lack a trusted checksum journal and become failed with blocked processing connectors. V3 journals keep trusted checksum recovery state. V4 failed/active footprints are reconstructed conservatively.

Invalid and duplicate files

Unsafe ids, filename/id mismatches and duplicate instance ids are not loaded. Their canonical candidates are moved without overwrite to unique .json.invalid[.N] files so evidence is not lost.

Failed-footprint quarantine

A failed job that may have mutated its bounded region keeps that region reserved in the world spatial index, including after restart. Inspect or repair the region first. Then run:

/csx instance clear-footprint <instance-id> <job-id>

The command synchronously saves the removal of the reservation. It does not inspect, restore or delete any block, block entity or schematic entity.

No destructive backtracking

Do not set backtrack-on-blocked true. Prior terrain, fluids, block-entity NBT, spawned entities, dispatched commands and later player/plugin changes cannot be reconstructed losslessly.
