Candidate preflight

Before queueing a module, CoreStructuresX transforms its bounds, checks the complete chunk footprint, verifies the radius from the structure origin, and evaluates collisions with generated modules, active jobs and persisted quarantines in the same world.

Projected hard limits

max-modules and max-open-connectors include queued, running, paused and otherwise recoverable jobs. Candidate connectors are added and the consumed parent connector is removed in the projection before admission. max-radius applies to every transformed corner.

Block whitelist and double pass

An enabled whitelist rejects a candidate when a target block is not replaceable. Optional double-pass overlap can reconsider an overlap with an already generated parent/module using real world blocks. It requires block checking and never bypasses a pending job reservation.

Bounded lookahead

Lookahead dry-runs future candidates to the configured depth with ALL_CONNECTORS or ANY_CONNECTOR. It is bounded by global node and time budgets. It does not mutate the world, reserve jobs, run real-block checks or replace closing behavior.

Closing without destructive rollback

When enabled, a normal limit transition enters CLOSING. Closing entries must be endpoints with zero CONNECTOR markers. CoreStructuresX never removes generated modules automatically because prior blocks, fluids, NBT, entities, commands and later external edits cannot be restored losslessly.

Immediately-before-write check

When the pack enables block checking, the runtime performs another exact whitelist check immediately before each world write. A failure after mutation may quarantine the job footprint so later instances cannot overlap an uncertain region.
