# CoreStructuresX website code index

## Public entrypoints

- `index.html` — Main landing/wiki/releases shell; loads public data and generated snapshots.
- `reference.html` — Full documentation reference shell.
- `features.html`, `installation.html`, `pack-authoring.html`, `configuration.html`, `docs.html`, `faq.html` — Legacy entrypoints redirected through `assets/js/legacy-routes.js` while preserving historical fragments.

## Product data and authored documentation

- `assets/js/data/site-config.js` — CoreStructuresX identity, verified Modrinth and issue links, Paper-only release matching, logo and theme tokens.
- `assets/js/data/landing-content.js` — Source-grounded product landing copy, feature cards, Paper setup, modes, FAQ and footer.
- `assets/js/data/docs-content.js` — Twenty-five article records, groups, hubs, navigation/search hints and five configuration mounts.
- `assets/content/docs/overview/` — Product capability, safety, authoring, state and compatibility boundary articles.
- `assets/content/docs/instructions/` — Requirements, layout, installation, reload and marker contract articles.
- `assets/content/docs/guides/` — Complete pack authoring, validation and troubleshooting articles; includes compatibility anchors from the former pack guide.
- `assets/content/docs/paper/` — Global config and bundled example pack/structure/group/command schema articles.
- `assets/content/docs/runtime/` — Data-version-5 persistence, backup, migration and failed-footprint recovery articles.
- `assets/content/docs/reference/` — Commands, permissions, production checklist and documentation evidence boundary.
- `assets/js/legacy-routes.js` — Deterministic legacy page/fragment to wiki-route mapping; exports `{ target, routes }` for contract tests.

## Shared runtime and presentation

- `assets/js/boot.js`, `app.js`, `docs.js`, `search.js`, `utils.js` — Theme boot, routing, wiki, search and shared interaction runtime.
- `assets/js/core/` — Landing, documentation, configuration, release, syntax and gallery renderers.
- `assets/css/` — Theme tokens and landing/wiki/release/gallery layouts.
- `assets/img/corestructuresx-logo.png` — Brand, favicon and static contain-mode hero image.
- `assets/vendor/highlightjs/` — Vendored syntax highlighter and license.

## Configuration synchronization

- `tools/config-sync-map.mjs` — Allowlist for `IceWolf23X/CoreStructuresX-plugin` ref `main`: global config plus four bundled example-pack YAML files.
- `tools/sync-plugin-configs.mjs` — Copies allowlisted logical text from an explicit plugin checkout and records source provenance.
- `tools/build-config-bundle.mjs` — Validates snapshots and builds the browser configuration bundle with SHA-256 metadata.
- `synced-configs/` — LF-normalized website snapshots and source state; generated by the sync workflow.
- `assets/js/generated/config-files.js` — Generated offline config bundle; do not edit directly.

## Documentation and releases tooling

- `tools/build-docs-bundle.mjs` — Validates article ids/body paths and generates the offline article bundle.
- `assets/js/generated/docs-bodies.js` — Generated offline documentation bundle; do not edit directly.
- `tools/build-releases.mjs`, `release-lib.mjs` — Optional public website release snapshot generation.
- `assets/js/generated/releases.js` — Generated public release snapshot; an empty catalog is valid.
- `tools/prepare-pages.mjs` — Coordinated static Pages preparation.

## Maintainer documentation

- `README.md` — Repository purpose, source model, sync/build commands and legacy URL statement.
- `SETUP.md` — Local preparation, preview and private-token boundary.
- `docs/CONTENT_MODEL.md` — Landing/catalog/article separation and id rules.
- `docs/CONFIG_SYNC.md` — Allowlist, provenance and credential rules.
- `docs/PRODUCT_REFERENCE.md` — Concise product/platform contract used to guard copy changes.

## Tests and automation

- `tests/` — Node contract, rendering, release, routing, bundle and Pages checks.
- `.github/workflows/` — Static verification, Pages and manual private-default synchronization workflows.

Build outputs, caches, archives, screenshots and binary plugin/schematic payloads are excluded from this index unless they have a specific maintained website responsibility.

## Shared validation contracts

- `assets/corestructuresx-logo.svg` — Retained public legacy logo URL; current brand and hero use the supplied PNG.
- `assets/js/data/ui-text.js` — Shared interface labels; product naming comes from site data and platform wording is Paper-only.
- `assets/js/docs.js`, `assets/js/search.js`, `assets/js/core/renderer.js` — Navigation uses catalog metadata (`navigation`, `hubs.instructionStarts`, `searchSuggestions`) rather than another plugin's article IDs.
- `tools/sync-plugin-configs.mjs` — `confinedPath` and `syncDefaults` preflight the declared YAML allowlist, reject path escapes/symlinks/descriptors, normalize LF and record committed-source provenance. The CLI refuses edited source defaults.
- `tests/config-sync.test.mjs` — Boundary, missing-source, normalization and idempotence checks.
- `tests/legacy-contract.json`, `tests/legacy-pages.test.mjs` — Independent baseline of old pages/bookmarks and tests of their maintained article/section targets.
- `tests/browser_docs_content.cjs` — Real offline Chromium validation of every article/config, reference, search, logo and responsive layout; requires an already installed Node Playwright runtime.
- `.gitattributes` — LF policy for authored HTML/data and stable normalized config snapshots.
