Purpose

commands.yml defines weighted command groups referenced by COMMAND marker line 3. The bundled test pack intentionally has no command groups.

Bundled example

Schema

commands-version: 1
groups:
  finish_room:
    entries:
      - weight: 1
        commands:
          - "say module {module} finished at {world} {x} {y} {z}"

Each group needs at least one valid positive-weight entry. commands may be one string, a list, or a map whose values are non-empty strings. One leading slash is optional and removed before dispatch.

Placeholders

{world} {x} {x+N} {y} {y+N} {z} {z+N}
{instance} {module} {schematic} {group} {source_group}
{uuid} {origin_x} {origin_y} {origin_z}

Coordinates are the transformed COMMAND marker position. Signed short offsets such as {y-2} are supported; out-of-range forms are left unchanged. The marker UUID is persisted across restarts.

Delivery semantics

Structural completion is committed first. Then the command record is marked consumed and saved before console dispatch. A crash after reservation but before Paper accepts the command can skip it; CoreStructuresX deliberately does not replay an external side effect.

A false dispatch result or exception is logged and not counted as successful, but the reservation remains consumed.
