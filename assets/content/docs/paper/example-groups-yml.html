Purpose

groups.yml maps connector group ids to weighted schematic candidates and optional fallback/closing routes.

Bundled example

Group schema

groups-version: 1
groups:
  path:
    entries:
      - schematic: corridor_01.schem
        weight: 10
    fallback-groups:
      - rooms
    closing-groups:
      - endpoints

Every group id is dynamic but must be safe. Every group needs at least one valid entry, and every fallback/closing reference must exist.

Entry schema

Each entry requires a confined schematic path and positive integer weight. It may provide an offset, marker replacements, and allow-overlap-with-parent. Legacy aliases height and overlap-on-parent remain accepted.

Offsets and replacements

An entry offset replaces the pack placement offset for that selected schematic. Replacement keys are ORIGIN, CONNECTOR and COMMAND; omitted keys keep global materials. Overrides affect paste planning, not marker detection.

Fallback groups

After all normal candidates fail, fallback groups are tried in listed order. Failed incremental recipes are remembered so one connector does not immediately repeat the same rejected work.

Closing groups

Every closing entry must reference an endpoint schematic with zero CONNECTOR markers. Completion occurs only after no open connector and no active job remains.
