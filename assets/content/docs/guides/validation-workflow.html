Strict YAML

With validation.strict: true, unknown keys are rejected at every fixed global, structure, group-entry, offset and command-entry level. Material maps and dynamic group ids remain intentionally dynamic.

Pack roots and ids

The loader enumerates direct children of the packs folder without following links. Symbolic-link, junction or reparse-point pack roots are rejected. All folders are grouped by declared id before publication; every duplicate definition is disabled with diagnostics.

Confined paths

Every pack YAML and schematic reference must be relative, lexically remain inside its configured root, and still resolve inside that root on the real filesystem. External links and sibling-prefix tricks do not pass validation.

Marker validation

  • At most one ORIGIN marker.
  • Every CONNECTOR group exists.
  • Every COMMAND group exists.
  • Every nonblank proximity radius is a positive integer.
  • Every connector in proximity mode has an explicit or positive default radius.

Graph validation

Closing entries must be endpoints. With require-all-connectors-resolvable, the loader analyzes every group reachable from the start group and rejects a closed cycle or branch without a finite endpoint path.

Validation commands

/csx validate
/csx validate pack <pack-id>
/csx packs list

The aggregate report shows its first 20 issues; use per-pack validation to inspect the complete selected report.
