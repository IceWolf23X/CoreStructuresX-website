One pack, one structure type

A direct child directory of plugins/CoreStructuresX/packs/ defines one pack. The pack id identifies its live instances and must be unique across every loaded folder.

Four YAML responsibilities

FileResponsibility
pack.ymlIdentity and confined paths to the other files and schematics directory.
structure.ymlStart group, facing, offsets, expansion mode, hard limits, checks and paste settings.
groups.ymlWeighted schematic entries, per-entry overrides, fallbacks and closing groups.
commands.ymlOptional weighted console-command groups used by COMMAND markers.

Schematics

Referenced schematic paths must remain inside the configured schematics folder after lexical and real-filesystem resolution. Absolute paths, traversal and external links are rejected. Each schematic should use one ORIGIN marker or a deliberately saved clipboard origin.

The module graph

The start group chooses the first module. CONNECTOR markers name the group used by each next edge. Fallback groups provide alternative candidates; closing groups provide zero-connector endpoints. With the default resolvability check, every reachable connector group needs a finite path to an endpoint.

Start with the smallest complete graph

Prove an entrance, a repeatable path and an endpoint before adding splits, stairs, commands, lookahead or parallel jobs. Validate and restart that small graph, then add one source of variation at a time.
