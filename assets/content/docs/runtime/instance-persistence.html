Data version 5

Every current canonical instance uses data version 5. The filename is derived from a safe [a-z0-9_-]+ instance id. Filename/id mismatches, unsafe ids and duplicate definitions are excluded before publication.

Saved state

The JSON graph includes origin, mode overrides, generated modules, spatial bounds, connectors, proximity triggers, command reservations, lifecycle state, sequences and complete recoverable paste journals.

Revisions and ordered checkpoints

The server thread assigns monotonic revisions and captures detached state only when a checkpoint is due. One ordered daemon writer serializes, flushes and atomically replaces snapshots. Per-instance submissions are coalesced and stale revisions cannot replace newer state.

Checkpoint schedule

The global interval, operation threshold and phase-boundary flag determine periodic cursor checkpoints. Transactional lifecycle changes, first-mutation intent, finalization and shutdown still use synchronous commits where durability gates a world/runtime effect.

Finalization

A paste enters FINALIZING with its job record still recoverable. The complete detached final state is saved before new module, connector, trigger or command state becomes visible. A failed final commit leaves finalization pending for retry.

Restart validation

Startup rebuilds jobs only when pack, schematic, transformed paste recipe, operation counts and invariants match the journal. A mismatch blocks the job and parent connector instead of continuing with changed inputs.

Checkpoint failure

A failed asynchronous checkpoint pauses the affected instance, releases its chunk tickets, records the reason and prevents further mutation until the storage problem is corrected and the instance is resumed.
